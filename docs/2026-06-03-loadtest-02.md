## 테스트 목적

2차 테스트는 1차에서 구성한 Docker 모니터링 환경을 바탕으로 공개 GET API 요청 범위를 넓혀 서버 안정성을 확인하는 테스트입니다.

홈 화면, 화면 설정, 게시판, 회식맵, 랭킹, 실기 카탈로그처럼 사용자가 반복 접근할 수 있는 읽기 요청을 중심으로 점검했습니다.

## 테스트 대상

대표 테스트 대상은 다음과 같습니다.

| 구분 | 예시 경로 |
|---|---|
| 홈 | `/` |
| 화면 설정 | `/api/screen-settings` |
| 수업 일정 | `/api/class-schedules` |
| 회식맵 | `/api/mealmap/places` |
| 필기 카탈로그 | `/api/exam-catalogs` |
| 실기 카탈로그 | `/api/ipep/exam-catalog` |
| 랭킹 | `/api/ranking` |
| 게시판 | `/api/notices`, `/api/posts` |

## 부하 조건

공개 GET API 테스트는 단계적으로 가상 사용자 수를 늘리는 방식으로 구성했습니다.

```text
30초 동안 10 VU
30초 동안 30 VU
30초 동안 50 VU
30초 동안 20 VU
30초 동안 0 VU로 감소
```

## 관찰 지표

- HTTP 요청 수
- p90, p95, p99 응답 시간
- HTTP 실패율
- 5xx 에러 여부
- endpoint별 요청 분포
- Grafana dashboard의 RPS와 VU 변화

## 결과 해석

2차 테스트는 전체 서비스의 공개 조회 API가 반복 요청 상황에서 서버 오류 없이 응답하는지 확인하는 데 의미가 있습니다.

인증이 필요한 기능이나 DB 변경이 발생하는 POST 요청은 제외하고, 배포 전 기본 안정성 확인에 필요한 읽기 요청만 다뤘습니다.

## 개선 방향

- 문제은행처럼 응답 크기가 크거나 DB 조회가 많은 API를 별도 테스트로 분리합니다.
- 인증이 필요한 API는 브라우저 요청 구조를 확인한 뒤 별도 시나리오로 구성합니다.
- 원시 로그 대신 공개 가능한 요약 지표만 문서로 남깁니다.
