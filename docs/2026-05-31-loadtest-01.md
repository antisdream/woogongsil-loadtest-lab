## 테스트 목적

1차 테스트는 우공실 성능 검증을 위한 Docker 기반 테스트 환경을 만드는 데 초점을 둔 기준 테스트입니다.

본격적인 부하 테스트에 앞서 k6, Prometheus, Grafana를 함께 실행하고, 우공실 로컬 서버에 반복 요청을 보내면서 지표를 수집할 수 있는지 확인했습니다.

## 테스트 환경

| 항목 | 내용 |
|---|---|
| 부하 도구 | k6 |
| 지표 수집 | Prometheus remote write |
| 시각화 | Grafana dashboard |
| 테스트 대상 | 우공실 로컬 백엔드 |
| 요청 방식 | 읽기 중심 GET 요청 |

## 확인 범위

- Docker Compose 기반 모니터링 스택 실행
- Prometheus remote write 수집 가능 여부
- Grafana datasource와 dashboard 연결
- 우공실 백엔드 기본 응답 여부
- smoke test 기준의 응답 시간과 실패율 확인

## 테스트 시나리오

초기 테스트는 서버가 정상 응답하는지 확인하는 smoke test 성격으로 진행했습니다.

```text
사용자 요청
→ k6 GET 요청
→ 우공실 로컬 백엔드 응답 확인
→ Prometheus 지표 수집
→ Grafana dashboard 확인
```

## 주요 확인 결과

- Docker 기반 모니터링 스택을 실행할 수 있음을 확인했습니다.
- k6 결과를 Prometheus로 전달하고 Grafana에서 확인하는 흐름을 만들었습니다.
- 이후 회차에서 동시 사용자 수와 테스트 대상 API를 늘릴 수 있는 기반을 마련했습니다.

## 개선 방향

- 단순 smoke test에서 공개 GET API 묶음 테스트로 범위를 넓힙니다.
- p95, p99 응답 시간과 HTTP 실패율을 함께 기록합니다.
- 테스트 결과를 회차별 문서로 분리해 비교 가능하게 관리합니다.
